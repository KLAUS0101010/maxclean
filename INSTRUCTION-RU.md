# MAX Clean: официальный MAX без слежки

GitHub берёт **официальный** APK MAX, меняет в нём только слежку и ссылки, подписывает и отдаёт готовый APK. Ставить больше ничего не нужно. Всё делается с телефона.

## Что меняется (всё остальное в APK остаётся байт в байт как в оригинале)

| Что | Как |
|---|---|
| **MyTracker** (VK): `tracker-api.vk-analytics.ru` | адрес → `0.0.0.0`; методы отправки (`flush`, `trackLaunchManually`, `trackLoginEvent`, `trackRegistrationEvent`) стали заглушками. `initTracker`, `getTrackerParams`, `handleDeeplink` не тронуты: MAX их вызывает при входе и при открытии ссылок |
| **VK Tracer**: `sdk-api.apptracer.ru` (краши, профилировщик, дампы памяти, диск) | адрес → `0.0.0.0` |
| **Аналитика звонков OK** внутри MAX | `send` и `forceSendScheduledEvents` стали заглушками, `initialize` не тронут, звонки работают |
| **Собственная аналитика MAX** (события и логи, которые приложение шлёт на свои серверы по основному соединению) | выключена встроенным переключателем приложения `analytics-enabled`. Весь код отправки сам спрашивает этот переключатель и просто выходит |
| **Рекламный ID** | убрано разрешение `AD_ID` |
| **Ссылки** | к каждому `max.ru` в манифесте добавлен `www.max.ru` с теми же правилами |
| Название на экране | «MAX Clean» |

Не трогаем: сервера `api.oneme.ru` (сообщения, вход, push), звонки (`api.ok.ru`), Firebase Installations (нужен для push).

## Чего это не делает (честно)
- То, что приложение шлёт на серверы самого MAX ради работы (номер, сообщения, IP, время входа), остаётся: иначе мессенджер не работает.
- Подпись у сборки другая, поверх обычного MAX она не встанет: сначала удалите обычный.
- Я не мог запустить сборку на настоящем APK. Тесты шли на макете с настоящим apktool. Если сборка упадёт, пришлите последние 30 строк красного шага.

## Шаг 1. Положить MAX.apk, чтобы у GitHub была прямая ссылка
1. В репозитории: **Releases → Create a new release**, тег `src`.
2. Прикрепите `MAX.apk` (один обычный APK, не `.apks` / `.xapk`), **Publish release**.
3. На странице релиза нажмите на файл `MAX.apk` и скопируйте адрес ссылки:
   `https://github.com/ВАШ_НИК/maxclean/releases/download/src/MAX.apk`

После сборки релиз с оригиналом лучше удалить.

## Шаг 2. Запустить сборку
1. **Actions → Build MAX Clean → Run workflow**.
2. В `apk_url` вставьте ссылку, `publish` оставьте `false`, **Run workflow**. Ждать 10–20 минут.
3. Внизу страницы сборки в **Artifacts** три файла:

| Файл | Что это |
|---|---|
| **MAX-Clean-full** | всё из таблицы выше. **Ставьте его** |
| **MAX-Clean-minimal** | только адреса трекеров → `0.0.0.0`, манифест и всё остальное как в оригинале |
| **MAX-Clean-control** | оригинальный MAX, просто переподписанный нашим ключом, без единой правки |

Сборка сама проверяет результат: тесты патчера, что список файлов совпал с оригиналом, что манифест не «поплыл» (ресурсы на месте), что имя пакета, версия и стартовая активность те же, что подпись корректна. Если проверка не прошла, шаг покраснеет и покажет причину.

## Шаг 3. Установить
Удалите обычный MAX (подготовьте SIM для кода), поставьте `MAX-Clean-full.apk`, разрешите установку из этого источника.

## Если что-то не работает: как найти виновника
Все три варианта подписаны одним ключом, их можно ставить друг поверх друга, вход сохранится.

1. Поставьте **control**. Если уже он не пускает или кнопки не работают, виновата сама подпись (сервер или приложение не принимают чужую), и патч тут ни при чём.
2. Если control работает, поставьте **minimal**, потом **full**. Запишите, на каком сломалось, и пришлите мне: например, «control работает, minimal работает, full нет». Это сразу покажет, что виновато: адреса трекеров, заглушки/переключатель аналитики или манифест.

## Ссылки max.ru и www.max.ru
Манифест теперь принимает оба адреса, и приложение разбирает ссылку по пути, а не по хосту. Но Android 12+ не открывает ссылки в приложении автоматически, если подпись не совпадает с подписью разработчика. Один раз включите вручную:
**Настройки → Приложения → MAX Clean → Открывать по умолчанию (Open by default) → Добавить ссылки → отметить `max.ru` и `www.max.ru`.**
Это ограничение системы, патчем его не обойти.

## Если сборка красная
| Проблема | Что делать |
|---|---|
| «This is not an .apk file» | Ссылка ведёт не на APK, или это bundle. Ссылка должна скачивать файл `MAX.apk` |
| `Cannot read field "format"` / `Could not smali file` | Ошибка apktool из-за версии кода; её обходит `dex_api.py`, он уже в сборке |
| «does not look like MAX» | В APK нет ни одного известного трекера: это не тот APK |
| `MANIFEST MISMATCH` | Пересобранный манифест не совпал с оригиналом. Присылайте вывод шага, **minimal** и **control** при этом всё равно соберутся |
| Другая ошибка | Последние 30 строк красного шага мне |

Обновление MAX: повторить шаги 1–3 с новым APK. Патчер ищет классы по сигнатурам (имена MyTracker, CallAnalyticsSender, ключ `analytics-enabled`), но обфусцированные имена могут измениться, тогда в логе будет предупреждение `WARNING`.

## Важно
- Собранное приложение рассчитано на Android 8.0+.
- Это правка вашей копии для себя. Раздавать такой APK другим нельзя: это нарушает правила сервиса и авторские права на MAX.
